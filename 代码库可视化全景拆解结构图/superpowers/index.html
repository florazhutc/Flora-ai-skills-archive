🏗️ 五层积木塔

这个系统像一栋五层的房子，每层有不同的功能。越往上越接近用户，越往下越底层。

第 5 层 · 触发器
🎯

自动触发层 (hooks/)

这个系统的"感应器"。它会监听用户和 AI 的对话，当检测到要"写代码"、"修 bug"、"做计划"时，自动激活对应的技能。

第 4 层 · 技能库
🛠️

技能定义层 (skills/)

14 个"武功秘籍"。每个技能告诉 AI 怎么做一件事：怎么写计划、怎么debug、怎么做code review。

第 3 层 · 编排
🎭

工作流编排层 (workflow)

把多个技能串起来。设计 → 计划 → 执行 → 测试 → review → 合并，形成完整的开发流程。

第 2 层 · 适配器
🔌

多平台适配层 (.claude/, .cursor/, etc.)

让技能能在不同 AI 工具里工作。Claude Code、Cursor、OpenCode、Codex、 Gemini CLI 都能用。

第 1 层 · 配置
⚙️

元配置层 (package.json, plugin.json)

项目的"身份证"。声明名字、版本、入口文件，让各平台能识别和加载这个插件。

⚡ 核心功能场景

这个工具能做什么？按重要程度排序，最常用的排在最前面。

1

🧠 先想后做（Brainstorming）

这是 Superpowers 的核心超能力。当你想做点啥，AI 不会直接上手写代码，而是先问你一堆问题，帮你把想法理清楚。它会保存设计文档，等你确认后再往下走。

用户："帮我做个用户登录" → AI："先别急，你希望用户怎么登录？邮箱？手机？第三方？"
2

📝 写详细计划（Writing Plans）

设计确定后，把任务拆成小块。每小块 2-5 分钟能做完，有具体的文件路径和验证步骤。像给一个"热情但没品味"的初级工程师写说明书。

"第 1 步：创建 src/auth/login.js，导出 login 函数，接受 email 和 password" → "第 2 步：运行 npm test 验证"
3

🤖 子代理开发（Subagent Driven Dev）

把计划里的每个任务交给一个"子 AI"去做。做完后有两轮审查：第一轮检查是否符合设计，第二轮检查代码质量。AI 可以自动工作几个小时。

主 AI 派任务给子 AI："你去实现登录功能" → 子 AI 做完了 → 主 AI 审查："符合设计吗？代码质量OK吗？"
4

🧪 测试驱动开发（TDD）

写代码前先写测试。遵循红/绿/重构的循环：先写一个失败的测试（红），写最少的代码让它通过（绿），然后再优化（重构）。

先写测试："login('a@b.com', 'wrong') 应该返回错误" → 测试失败 → 写代码让测试通过 → 重构优化
5

🔧 系统化调试（Systematic Debugging）

遇到 bug 时不靠猜测，而是用 4 步流程：观察现象 → 收集证据 → 追踪根因 → 修复验证。还有防御性编程和条件等待等高级技巧。

"页面卡住了" → 先观察：哪个操作后卡住的？ → 收集：浏览器控制台有什么错误？ → 追踪：找到是哪个函数超时 → 修复并验证
6

👀 代码审查（Code Review）

任务之间会触发代码审查。对着计划检查代码，按严重程度分类问题。严重的问题会阻止继续开发。

"🔴 严重：登录逻辑完全错了" + "🟡 中等：变量名不一致" + "🟢 小事：注释可以更清楚"
7

🌿 Git 工作树（Git Worktrees）

在独立分支上开发，用 git worktree 创建隔离的工作目录。不影响主分支，可以同时开发多个功能。

设计通过 → 创建新分支 feature-login → 用 worktree 开一个独立工作目录 → 开始实现
8

🏁 完成任务（Finishing a Branch）

所有任务完成后，验证测试，然后给你几个选择：合并到主分支、创建 PR、保留分支、或者放弃。还会清理 worktree。

"任务都做完了！测试通过。要合并吗？还是先创建 PR？或者先留着？"

💬 这群"人"是怎么配合干活的？

一个用户想做一个"用户登录功能"。完整展示每个环节谁在干活。

👤
用户
"帮我做个用户登录功能。"
🧠
Brainstorming（思考引导）
"先别急！帮我理清需求：
1. 用户怎么登录？邮箱？手机？
2. 要支持第三方登录吗？Google？GitHub？
3. 需要记住登录状态吗？
4. 密码忘了怎么办？"
👤
用户
"邮箱+密码登录，不需要第三方，记得登录状态。"
📋
Spec Document（设计文档）
"设计文档已保存：
• 登录页面 /login
• POST /api/auth/login
• 返回 JWT token
• 7天有效期的 cookies
• ..."
👤
用户
"好的，按这个来。"
📝
Writing Plans（写计划）
"计划已生成，共 8 个任务：
1. 创建 src/auth/login.js，导出 login 函数
2. 创建 src/auth/validate.js，验证邮箱格式
3. 创建 src/middleware/auth.js，JWT 验证中间件
4. ..."
👤
用户
"开始吧！"
🤖
Subagent Driven Dev（子代理开发）
"[派任务] 子代理 A，去做任务 1-3
[结果] 子代理 A 完成了 login.js
[审查] 主 AI：'符合设计，继续下一批任务'"
🧪
TDD（测试驱动开发）
"[红] 测试失败：login() 应该返回错误当密码错误
[绿] 写代码通过测试
[重构] 优化代码结构"
🤖
Subagent Driven Dev（继续执行）
"[派任务] 子代理 B，去做任务 4-6
[派任务] 子代理 C，做任务 7-8
[完成] 8 个任务全部做完"
👀
Code Review（代码审查）
"审查结果：
🔴 严重：无 - 登录逻辑正确
🟡 中等：2 个（变量名不一致、缺少错误处理）
🟢 小事：3 个（注释可更清楚）"
👤
用户
"修复中等的问题，然后完成。"
🏁
Finishing Branch（完成任务）
"测试全部通过！
请选择：
1. 合并到 main 分支
2. 创建 PR
3. 保留分支继续开发
4. 放弃"

📚 大白话百科

这些词儿到底什么意思？用日常例子讲给你听。

Skill（技能）
像"工作手册"。告诉 AI 在某种情况下该怎么做一件事。 Superpowers 有 14 本手册。
Hook（触发器）
像"感应开关"。当你说特定的话（如"帮我做个功能"），它会自动打开对应的技能。
Subagent（子代理）
像"包工头"。主 AI 把任务交给子 AI 去做，自己做审查和协调。可以同时派多个"人"干活。
TDD (测试驱动开发)
像"先出考题再上课"。老师先出题，学生答不出来 → 老师上课教 → 学生答对了 → 再出下一题。
Red/Green/Refactor
像"三步走"：红灯（测试挂）→ 绿灯（代码写完测试过）→ 黄灯（优化代码）。
YAGNI
像"别买用不上的东西"。你现在不需要的功能，别提前写。避免过度设计。
DRY (Don't Repeat Yourself)
像"别重复抄作业"。同样的代码不要复制粘贴，写一次然后复用。
Git Worktree
像"同时开多个文件夹"。在一个仓库里开多个独立目录，同时做不同的事情，互不干扰。
