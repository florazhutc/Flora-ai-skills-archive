⚡ 核心功能

📋 规范驱动开发

Spec-Driven Development - 在写代码前先写 PRD，包含目标、结构、代码风格、测试和边界。

🧩 增量实现

Incremental Implementation - 薄垂直切片：实现→测试→验证→提交，功能开关、安全默认值。

🧪 TDD 测试驱动

Test-Driven Development - 红-绿-重构，测试金字塔（80/15/5），先写测试再写代码。

🔒 安全加固

Security & Hardening - OWASP Top 10 预防、认证模式、密钥管理、三层边界系统。

🚀 自动化发布

CI/CD & Automation - 左移、质量门禁流水线、功能开关、分阶段发布、回滚方案。

📝 代码审查

Code Review - 五轴审查，变更大小约 100 行，严重性标签，审查速度规范。

🛠️ Slash 命令工具箱

/spec

Define 规范

在写代码前先定义清楚要做什么，包含目标、验收标准和实现方案。

/plan

Plan 规划

把大需求拆成小任务，排好顺序和依赖关系，形成可执行计划。

/build

Build 构建

增量实现，每次只做一小块，确保每次提交都能跑通测试。

/test

Test 测试

证明功能真的能用，写测试用例，覆盖各种边界情况。

/review

Review 审查

代码质量审查，检查安全性、性能、可维护性和代码规范。

/ship

Ship 发布

执行发布流程：检查单→分阶段发布→监控设置→回滚方案。

📖 大白话解释

什么是 Agent Skills？

想象你开了一家软件公司，Agent Skills 就是你雇的一群超级专业的工程师：有人专门做设计规划，有人专门写代码，有人专门测试，有人专门做安全审查。遇到什么问题，就叫对应的工程师来处理。

Slash 命令是什么？

就像在Slack里打 /call 能叫人来开会一样，输入 /plan 就能叫"规划师"来帮你拆任务，输入 /review 就能叫"审查员"来帮你审查代码。

薄切片实现是什么？

就像吃披萨，一口吃不完，要切成一小块一小块吃。Incremental Implementation 就是这个意思：不要憋一个大功能写半天，而是分成很小很小的功能点，每个点都能独立运行、独立测试。这样好处是：哪里出问题一眼就能看出来。

TDD 为什么要先写测试？盖房子先做模型？

就像盖房子前先做模型测试风阻一样，TDD (Test-Driven Development) 要求先写测试再写代码。这样做的好处是：你得先想清楚"什么才算成功"，然后再奔着那个目标去实现，不会写着写着跑偏了。
