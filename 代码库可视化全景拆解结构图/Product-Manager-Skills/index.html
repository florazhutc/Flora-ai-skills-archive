适合谁

产品管理：适合 PRD、路线图、用户故事、JTBD、定价和 SaaS 指标分析。

Codex 用法

优先按具体技能或原项目安装方式使用，不建议把归档目录整包复制。

npx skills add deanpeters/Product-Manager-Skills --skill prd-development -a codex -g

许可证 / 风险

CC BY-NC-SA 4.0；商业复用需谨慎。

最常用 5 个技能

prd-development 写 PRD；user-story 写用户故事；roadmap-planning 做路线图；jobs-to-be-done 做需求洞察；prioritization-advisor 做优先级判断。

按任务选择

调研用 company-research / discovery-interview-prep；方案用 problem-framing-canvas / recommendation-canvas；商业判断用 finance-based-pricing-advisor / saas-revenue-growth-metrics。

使用建议

一次只装一个明确 skill。让 Codex 先问 3 个澄清问题，再按技能输出结构执行，结果会比泛泛提示稳定。

🎯 核心理念

ABC — 永远在教导

这个技能包不仅让 AI 代理更强，也让产品经理自己变得更厉害。每项技能都应该让使用者学到新东西。

🎓 教学优先 (Pedagogic-First)

删除解释来精简输出是一个缺陷，不是优化。每一项技能都要留下学习阶梯，让 PM 在使用过程中理解"为什么这个框架有效"。

🤝 双重服务

技能同时服务于两个目标：让 AI 代理能执行专业工作，让人类 PM 学会专业思维。两者都不是副产品。

📚 脚手架学习

不要假设用户什么都懂。每项技能都要包含足够的上下文，让初学者也能理解并应用。

技能库

46 种经过实战检验的 PM 技能，覆盖产品管理全流程

📋
组件技能 20 个

Altitude Horizon Framework 领导力

理解 PM 到总监的转变，通过" altitude 视角"和"horizon 视野"两个维度诊断领导力差距。

📝 大白话：就像从看一张桌子提升到看整个房间 —— 你需要看得更广、更远。

Company Research 调研

创建公司研究简报，包含高管引言、产品战略和组织背景，用于竞品分析或面试准备。

📝 大白话：做"尽职调查"——像侦探一样收集目标公司的公开信息。

Customer Journey Map 用户

创建客户旅程地图，涵盖阶段、触点、行动、情感、指标，诊断体验断裂或团队对齐。

📝 大白话：画出用户从"听说"到"推荐"的全过程，找出哪里让他不爽。

EOL Message 沟通

撰写清晰、有同理心的停运公告，包含理由、用户影响和下一步，避免不必要的困惑。

📝 大白话：像写"分手信"——诚实但温柔，给对方一个明确的过渡方案。

Jobs To Be Done 需求

用 JTBD 格式系统化地揭示客户的工作、痛点和收益，应用于需求澄清或产品定位。

📝 大白话：搞清楚用户雇你的产品"完成什么任务"，而不是他"想要什么功能"。

Lean UX Canvas 设计

创建精益 UX 画布，连接用户问题、假设、解决方案和关键指标，快速验证想法。

📝 大白话：一页纸的"创业画布"，让你的想法先在纸上跑通。

Opportunity Solution Tree 机会

构建机会解决方案树，从结果向下展开到机会点、解决方案和实验，防止目标漂移。

📝 大白话：从"我们要解决什么问题"倒推"做什么功能"，而不是反过来。

PESTEL Analysis 战略

用政治、经济、社会、技术、环境、法律六个维度分析外部环境，支撑战略决策。

📝 大白话：给公司照个"全身 X 光"，看看外面有什么因素在影响它。
💬
交互技能 20 个

Acquisition Channel Advisor 获客

用单位经济学、客户质量和可扩展性评估获客渠道，决定是扩大、测试还是放弃。

📝 大白话：算账——这个获客渠道是赚钱还是赔钱？要不要继续投钱？

AI Shaped Readiness Advisor AI

评估你的产品工作是"AI 加持"还是"AI 驱动"，诊断 2026 年 PM 需要的关键 AI 能力。

📝 大白话：给你的"AI 能力"打分，看看是停留在"用 AI 工具"还是"用 AI 思维"。

Business Health Diagnostic 诊断

通过增长、留存、单位经济和资本效率诊断 SaaS 业务健康状况，生成健康评分卡。

📝 大白话：给公司做"体检"——检查增长率、用户留存、赚钱能力是否正常。

Context Engineering Advisor 提示词

诊断你是"塞太多内容"还是"精心设计上下文"，解决 AI 工作流过于臃肿或不可靠的问题。

📝 大白话：别给 AI 喂太多垃圾——给它精准的上下文，它才能给你精准的答案。

Customer Journey Mapping Workshop 工作坊

运行一个客户旅程映射工作坊，用自适应问题引导团队画出用户全流程的痛点和机会。

📝 大白话：把团队聚在一起，边聊边画，找出用户在哪里受苦。

Director Readiness Advisor 晋升

指导 PM→总监的转型过程，通过自适应问题诊断你处于哪个阶段并提供实战建议。

📝 大白话：像请了个"职业教练"，帮你搞定从管功能到管人的转变。

Discovery Interview Prep 调研

准备客户发现访谈，设计目标、选择客户群、规划方法，避免确认偏差和表面反馈。

📝 大白话：别盲目去问用户"你想要什么"——先想好问什么、怎么问。

Epic Breakdown Advisor 拆分

用 Humanizing Work 方法将大型史诗故事拆分成可执行的用户故事，确保垂直切片。

📝 大白话：把一个"大功能"拆成"小功能"，像把披萨切成可吃的一块块。

Feature Investment Advisor 投资

用收入影响、成本结构和 ROI 评估功能投资价值，做出 build/don't build 决策。

📝 大白话：算这个功能值不值得做——投入多少开发资源，能带来多少收入？

Finance Based Pricing Advisor 定价

用 ARPU、转化率、流失风险、NRR 和回本周期评估定价变动的财务影响。

📝 大白话：涨价前先算账——涨多少会流失多少用户？会不会因小失大？
⚡
工作流 6 个

Discovery Process 完整流程

从问题假设到验证解决方案的完整发现周期：问题框架→客户访谈→综合→实验。

📝 大白话：像做"科学实验"——先猜一个假设，再去验证它是对是错。

Executive Onboarding Playbook 高管入职

VP/CPO 的 30-60-90 天诊断入职路径——先理解再行动，避免过早改变。

📝 大白话：新官上任"先观察再放火"——前三个月只诊断，不急着改。

Product Strategy Session 战略

从定位到机会再到路线图决策的完整产品战略构建流程。

📝 大白话：像给公司写"五年计划"——先想清楚我们在哪里，要去哪里。

PRD Development 需求文档

创建可决策的 PRD，链接问题框架、需求定义和故事脚手架。

📝 大白话：写一份"需求清单"，让开发知道做什么、为什么做、做到什么程度。

Roadmap Planning 规划

将战略和验证的机会转化为有明确取舍的排序路线图。

📝 大白话：排出"优先级"——哪些先做、哪些后做、为什么这么排。

User Story Mapping 用户故事

创建用户故事地图，可视化用户旅程并将其转化为可规划的发布切片。

📝 大白话：把用户要用你的产品做的所有事画成一张"地图"，然后切块交付。

框架来源

这些技能基于世界顶级的产品管理框架和思想领袖的研究

🎯 Teresa Torres — 持续发现与迭代

强调产品经理应该"永远在发现"，通过持续的用户访谈和实验来验证假设，而不是一次性的调研。

来源：Teresa Torres《The Continuous Discovery Habits》

🎯 Geoffrey Moore — 技术采用生命周期

解释了为什么新技术产品先要在早期采用者中站稳脚跟，才能跨越"鸿沟"进入主流市场。

来源：Geoffrey Moore《Crossing the Chasm》

🎯 Amazon — 逆向工作法

从客户想要的终态倒推回来设计产品和功能，而不是从技术能力出发"堆"功能。

来源：Amazon 内部方法论

🎯 MITRE — 系统工程思维

用系统工程的视角来看产品开发，关注整体性能、成本、风险和权衡，而不是单个功能的酷炫程度。

来源：MITRE 系统工程指南

🎯 Marty Cagan — 价值与风险的平衡

产品成功的关键是在"解决用户问题"和"技术可行性"之间的平衡，PM 的核心职责是创造价值。

来源：Marty Cagan《Inspired》

🎯 Lean UX — 快速验证

用最少的代码验证最大的假设，通过"设计冲刺"快速迭代，避免长时间开发后发现方向错了。

来源：Jeff Gothelf & Josh Seiden
